# 저녁 업무 정리 (daily-work-record)

portable-agent-kit의 선택 모듈 `modules/daily-work`의 스킬이다. 키트 루트는 `AGENTS.md`와 `modules/`를 가진 디렉터리이며 cwd로 가정하지 않는다.

먼저 `AGENTS.md`, `core/principles.md`, `modules/daily-work/README.md`, `local/profile.md`, `local/daily-work/sources.md`, 대상 날짜의 기존 기록을 읽는다. `sources.md`가 없으면 멈추고 예시 파일 복사를 안내한다.

날짜 경계와 시간대는 `local/profile.md`를 따르며, 없으면 시스템 시간대를 쓰고 이를 기록한다. 날짜가 없으면 오늘을 쓴다. 실제 수집 시각을 남기고, 저녁 마무리면 "마감", 중간 정리면 "부분 수집"으로 표시한다. 마감 뒤 같은 날 다시 호출해도 추가 활동을 반영한다. 해당일 `resume.md`가 있으면 아침 계획과 비교하되, 계획을 수행한 것으로 간주하지 않는다.

기록 저장소에 origin이 있으면 로컬 변경을 확인하고 fetch한다. 작업 트리가 깨끗하고 fast-forward 가능할 때만 동기화하며, 다른 기기의 기록이나 로컬 변경을 덮어쓰지 않는다.

## 근거 수집

- **Git (필수)**: `sources.md`의 원격 식별자로 각 기기의 로컬 경로를 찾는다. `local/daily-work/paths.local.json`(git 제외)이 있으면 참고하되 실제 remote를 검증한다. 작업공간 도구(worktree 관리자 등)가 설정돼 있으면 그 도구로 관련 worktree를 모두 찾고, 기본 체크아웃 하나로 수집을 제한하지 않는다. 다른 작업공간을 수정하지 않는다.
  - 각 worktree의 브랜치, 전체 HEAD SHA, 작업 트리 상태, 원격 push 여부를 확인한다.
  - 관련 ref 전체의 log를 날짜 경계로 조회하고, 작성자/커미터 시각 차이를 고려한다. 같은 SHA는 한 번만 기록하고 본인 활동인지 확인한다.
  - 커밋 메시지, 필요한 diff, PR, 검증 근거로 실제 작업과 결과를 요약한다. 실행하지 않은 검증은 통과로 쓰지 않는다.
  - 미커밋 변경이 존재한다는 것만으로 오늘 만든 변경이라고 단정하지 않는다.
- **이슈 트래커 (선택)**: 읽기 도구로만 조회하고 페이지를 끝까지 읽는다. 담당자 조회, 해당일 본인 상태 변경, 로컬 작업에서 발견한 티켓 키를 조합하고 댓글·작업 로그도 확인한다. 검색 조건과 조회 범위를 남긴다. 변경 이력에서 실제 변경자, 대상일 시각, 이전→이후 상태를 확인한다. 오늘 갱신된 티켓의 과거 변경을 오늘 변경으로 적지 않고, 담당자라는 이유만으로 본인이 수정했다고 판단하지 않는다. 티켓을 변경하거나 작업 로그를 등록하지 않는다.
- **캘린더 (선택)**: 계정과 캘린더 목록을 확인한 뒤 같은 날짜 구간의 이벤트를 페이지 끝까지 읽는다. 반복 일정과 공유 캘린더 중복을 제거한다. 취소·거절·종일 일정은 회의 시간 합산에서 제외한다. 예정, RSVP, 실제 참석 근거를 구분하며 참석 근거가 없으면 "참석 미확인"으로 적는다. 캘린더를 편집하지 않는다.
- **에이전트 활동 (선택)**: 접근 가능한 작업 세션과 사용자 메모를 시간과 결과의 보조 근거로 쓴다. 전체 대화는 저장하지 않는다.
- **지침·스킬 변경**: 대상 저장소와 이 기록 저장소의 `AGENTS.md`, `CLAUDE.md`, 스킬 디렉터리(`.agents/skills`, `.claude/skills`, `.gemini/skills`)의 Git 이력과 현재 변경을 확인한다. 상대 경로, 변경 이유, 행동 변화, 커밋/해시, 다른 기기 적용 방법을 기록한다. Git 밖 파일은 `records/YYYY-MM-DD/instructions.sha256`에 해시를 남기고 이전 기록의 해시와 비교하며, 처음 본 파일은 기준선으로 표시한다. 형식은 첫 줄에 `# 관측: <ISO 시각>`, 이후 `<SHA-256>  <저장소 이름>/<상대 경로>`이며, `/`로 끝나는 경로는 디렉터리 전체 파일 내용의 집계 해시다. 원본 내용은 저장하지 않는다. 수정 시각(mtime)만으로 변경 시각과 내용을 확정하지 않는다.

조회에 실패한 소스는 실패 사유와 미수집 범위를 남긴다. 자료 미수집을 "활동 없음"으로 바꾸지 않는다.

## 시간 책정

사용자 확정 시간, 실제 구간이 있는 활동, 작업 로그, 추정 시간을 구분한다. 작업별로 분 단위 값이나 범위, 근거, 신뢰도를 적는다. 커밋 사이 간격은 실작업 시간이 아니다. 근거가 약하면 "미확인"으로 두고 부족한 증거를 적는다.

같은 작업의 Git, 이슈, 세션은 하나의 활동으로 합친다. 회의와 작업이 겹치는 구간은 총합에 한 번만 넣는다. 실제 구간이 있는 시간은 구간 합집합으로 계산하고, 구간 없는 신고 시간과 추정은 별도 소계로 둔다. 예정 회의 시간과 참석 시간을 합치지 않는다. 근거 없이 전체 근무시간을 채우지 않는다.

## 저장

`modules/daily-work/templates/daily.md`, `handoff.md`를 읽어 `records/YYYY-MM-DD/daily.md`, `handoff.md`를 작성한다.

- 업무에는 결과, 진행/완료, 검증 범위, 다음 행동, 출처를 붙인다.
- 인수인계에는 원격 저장소, 브랜치, 전체 SHA, push 확인 여부, 미커밋 파일 경로와 전달 필요성, 티켓/PR, 지침 변경 적용 경로를 넣는다. 불확실한 항목은 "미확인"으로 둔다.
- 다시 수집하면 SHA, 티켓 이력 ID, 이벤트 ID와 시각으로 중복을 합친다. 사용자 정정과 확정 시간은 보존한다. 재조회 범위가 줄었다고 기존 항목을 지우지 않는다.
- API 응답, 전체 소스, 대화, 첨부, 패치 복사본을 저장하지 않는다. 비밀과 불필요한 개인정보를 제외한다.

## 동기화

링크, 날짜, 시간 중복, 필수 인수인계 항목을 확인하고 변경 파일과 수집 범위를 보고한다.

`local/daily-work/sources.md`의 `auto_commit`이 `true`이면, 이번 호출에서 작성한 기록 파일만 스테이징해 커밋하고 기록 저장소의 기본 브랜치로 push한다. 그 밖의 경우에는 커밋 제안만 하고 사용자 승인을 받는다.

- push 전에 origin이 private인지, 원격 기본 브랜치가 로컬 HEAD의 조상인지, 보낼 커밋이 이 기록 저장소의 의도한 변경뿐인지 확인한다.
- 기본 브랜치 또는 원격 기본 브랜치를 추적하는 기록 전용 브랜치(worktree 포함)에서만 push하며, `git push origin HEAD:<기본 브랜치>`처럼 대상 ref를 명시한다. 그 밖의 브랜치라면 임의로 전환하거나 merge하지 말고, 현재 기록을 보존한 채 동기화가 남았다고 보고한다.
- 기존 staged 변경은 포함하지 않는다. 원격이 앞서 있거나 push가 거절되면 force push 없이 로컬 결과를 보존하고 미동기화를 보고한다.
- 작업 대상 저장소의 커밋·push, 이슈·캘린더 변경은 이 절차에 포함하지 않는다.

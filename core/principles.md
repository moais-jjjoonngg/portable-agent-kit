# 공통 원칙

모든 키트 스킬이 따르는 원칙이다.

## 1. 비파괴

- 기본은 dry-run이다. 변경 계획(추가 / 변경 / 충돌 / 수동 조치)을 표로 먼저 보여준다.
- 사용자가 승인한 항목만 적용한다. 승인은 해당 실행에만 유효하다.
- 기존 파일을 바꾸기 전 같은 위치에 `<파일>.pak-bak-<YYYYMMDDHHMMSS>` 백업을 만든다.
- 이미 존재하는 다른 내용의 파일·디렉터리·링크는 덮어쓰지 않고 충돌로 보고한다.
- 같은 명령을 다시 실행해도 결과가 같아야 한다(멱등).

## 2. 비밀과 개인정보

- 토큰, API 키, OAuth 정보, HTTP 헤더 값, 비밀번호, 쿠키는 읽어도 기록하지 않는다.
- 환경변수는 이름만 기록한다. 예: `env: [GITHUB_TOKEN]`.
- 홈 디렉터리 경로는 `~`로 바꿔 기록한다. 기기마다 다른 절대 경로를 식별자로 쓰지 않는다.
- 인증이 필요한 MCP는 `auth: oauth | env | none`으로만 표시하고, 인증은 새 기기에서 사용자가 직접 한다.

## 3. 근거

- 설치 여부·버전·경로는 실제 명령 또는 파일 확인 결과로만 기록한다. 추측한 값은 `unverified`로 표시한다.
- 확인하지 못한 항목을 "없음"으로 바꾸지 않는다. 실패 사유를 남긴다.

## 4. 범위

- 키트 스킬은 에이전트 설정(지침, 스킬, MCP, hooks 요약, 관련 CLI 도구)만 다룬다.
- 에이전트 대화 기록, 캐시, 세션, 인증 파일(`auth.json` 등), 텔레메트리는 대상이 아니다.
- 패키지 설치 명령은 계획에 표시만 하고, 사용자가 승인한 경우에만 실행한다.
